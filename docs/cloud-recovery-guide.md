# 1.9.x 云备份与重装恢复指引

云备份保存 Native History 版本的完整依赖闭包，包括载荷、Manifest 和历史 Pack。只有这些对象均已验证且元数据同步完成，才显示“云备份完成”。本地备份成功并不表示云备份成功；“找回历史”只拉取元数据，恢复选定版本时才按需下载载荷。

## 配置连接

1. 在软件设置的运行环境中配置 rclone 可执行文件，通过“云连接管理”创建共享连接，或为指定项目创建专属连接。项目云设置及恢复入口使用同一向导。
2. WebDAV 可在向导中创建连接。其他 rclone 后端先用 rclone 完成认证，再选择明确的 `.conf` 文件和 remote。OAuth 连接须先“导入为受管凭据”；外部配置只能作为不会刷新 Token 的连接引用使用。不能依赖 rclone 默认配置路径。
3. 同一受管凭据文件可以供多个档案使用；共享与专属是可见性，不能把轮换 Token 随意复制成两套长期独立认证。向导显示同一凭据影响的项目数。
4. 选择项目远端根目录。`remote:path` 与 `remote:/path` 含义可能不同，保留原来的前导 `/`；`remote:` 和 `remote:/` 也不能互换。
5. 浏览或读取验证足够用于只读发现、拉取和恢复。要开启自动上传，须在本项目根目录通过独立的写入及读回验证，并保存连接。准备好工具不等于已经连接云账户。

共享连接目标变化会暂停引用项目的自动上传并清除旧验证。删除档案前须处理项目引用、受保护任务和未合并认证证据；删除档案不会删除云端数据或自动清理凭据。

## 自动、手动与待传任务

- 自动上传只接纳开关开启且写入验证有效之后的本机成功备份提交；不会因升级、开启开关或导入旧 History 而自动补传全部旧版本。
- 手动选择版本上传同样上传完整依赖闭包；已有副本须验证真实 Manifest 和载荷 SHA256 后才能复用。
- 在项目云向导查看任务 ID、阶段、保护状态和诊断。阶段包括依赖解析、上传、校验、元数据同步、待重试、暂停和需处理。失败不会回滚本地成功备份。
- 取消、关自动上传、退出或重试失败均保留待传载荷保护。只有云备份完整成功，或用户明确“放弃保护”，才解除保护。放弃保护不删除云端对象，也不表示该版本已备份；后续本地保留清理可能使它无法恢复。
- 为降低数据丢失风险，只要仓库有受保护任务或登记证据不确定，本轮实现保守暂停该仓库的物理清理，不仅保护当前选中版本。完成补传后再执行清理。

任务冻结原项目身份、连接及绑定修订、根目录、工作目录和凭据证据。改 remote、账户、端点、根目录等不会让旧任务改投新位置。正常、可证明的 Token 刷新可继续；无法证明的认证替换会暂停。更换云盘或根目录不提供历史连续性保障，不会自动迁移旧云数据。目标变化后的旧任务需要保留原访问方式处理，或对重要版本明确手动补传后再处置旧任务。

## 凭据与异常退出

受管凭据、受保护任务快照和刷新证据位于当前安装的统一配置目录下 `credentials/rclone`、`credentials/rclone-tasks`（以应用实际配置目录为准）。Token 只存于受保护 `.conf`，任务 Journal 和修订账本只记非秘密证据。支持的 OAuth Token 更新仅合并允许的 section/token 字段；未知后端、其他字段改变、源文件冲突、硬链接或重解析点路径会安全阻断。

Host 异常退出后，先核对记录的 rclone 子进程与稳定快照，再按原修订进行 CAS 合并。如果子进程仍运行、启动归属不能证明或源已改变，会保留快照并暂停该凭据；不会按文件时间猜新 Token，也不会将未知快照过期删除。日志或诊断导出不得包含 `.conf` 正文。

遇到认证冲突时先保留整个凭据目录及任务证据，确认旧子进程已结束。不要把旧配置覆盖已刷新的文件，不要手工删除未知快照让任务强行继续。无法安全回收时重新认证到新的明确配置，导入并验证连接；旧任务保持原证据，需要单独处理。当前没有自动丢弃冲突证据的修复按钮。

Journal 缺失、损坏或写入失败时，本地备份仍可继续，云登记与危险清理暂停。优先找回原 `local-state/cloud-jobs.json` 及相关证据。只有 Journal 确实缺失时，向导允许明确确认“仅初始化今后的接纳”：这会原子记录放弃未知旧保护的决定与新基线，不能修复现存损坏 Journal，也不会自动补传旧版本。重要旧版本应先补传或另行保全。

## OpenList

软件设置提供程序、工作目录、数据目录、配置文件及服务 URL。受管实例使用绝对路径，不能与备份源、仓库或 FolderRewind 配置存储重叠。首次授权会核对程序版本，并明确记录本机及环境签名；改程序或配置后需重新授权。

只有明确勾选“此连接依赖本机 OpenList”的档案才使用按需启动。HTTP 可达仅表示观察到端点，真实 WebDAV 权限仍需 rclone 读取/写入验证。外部已经运行的服务可以使用，但不授予停止权。

多个任务共享一次受控启动。完成上传、最小化托盘或退出 FolderRewind 后，OpenList 继续运行。手动停止只允许当前 FolderRewind 亲自启动、可核对路径/启动时间且无传输租约的进程；重启 FolderRewind 不会认领以前的实例。机器启动授权不随配置导出或跨设备导入传播。

## 有配置导出时恢复

1. 在新环境导入配置 JSON，选择迁移方式。原 ConfigId/SourceId 保留，本机工具路径、凭据及 OpenList 授权清除；正常备份与云上传保持迁移门控暂停。
2. 配置 rclone，重新取得访问凭据，选择原项目根目录。remote 在新机上可以改名，目录含义及云端仓库必须保持原样。
3. 在项目云向导使用“重新关联原仓库”。向导先读取实际 `repository.json` 并核对原 ConfigId，再保存绑定并只读拉取 Pack；身份不符时阻断。
4. 加载旧版本，查看恢复预览。Cloud Replica Fact 只是候选证据；选择版本后实际下载并核对所有依赖、Manifest、大小和 SHA256。
5. 选择新的空目录恢复。目标不能覆盖现有源、备份目录、配置目录或恢复仓库。核对文件内容后，再通过现有迁移设置确认路径、插件和运行环境，分别确认常规备份及云上传权限。

归档加密需另行提供原密码；rclone crypt 还需原 crypt 密码/盐。重新登录云账户不能替代解密材料。这些材料不会为了恢复被夹带到导出的 JSON。

## 没有配置导出时恢复

使用云恢复入口和临时只读连接发现 Native History 仓库，选择仓库、分析、选择版本并恢复到新目录。切换仓库、连接或目录会使旧分析与确认失效。此流程不重建所有项目、插件、自动化或机器设置；不向远端创建目录、上传 Pack 或补写 Manifest。

当前恢复引擎支持 Host 核心全量/滚动/智能增量归档。PluginArtifact 需要兼容 Handler；当前 Host 没有可用于此恢复入口的通用 PluginArtifact Handler，缺失时按诊断阻断，不能承诺插件版本完整恢复。插件产生的核心归档仍按其实际 Representation 类型处理。

## 配置导出及兼容边界

数据管理使用已有连接选择器。新云配置导出使用 `_folderrewind/config-exports/config-<UTC>-<GUID>.json`，保留以前的文件；导入时可选择文件，也兼容旧 `config.json`。配置导出不包含 Token、密码、`.conf` 正文、旧任意命令中的认证参数或机器 OpenList 授权。

v1.9.6 配置按旧字段保守升级为项目专属连接，保留原路径语义；旧自定义命令保留在本机安全副本并要求明确转换，不继续充当默认原生上传策略。Native Commit Pack format 1、repository format 2 和 StorageReplica 协议均未升级。v1.8.2 继续遵循已有迁移/告警路径，其旧云格式不自动转换为 1.9.x 原生云仓库。

实现与实际验证范围见 [验收记录](cloud-refactor-acceptance.md)。UI、真实云账户、MSIX 及双电脑发布验收须按该清单人工完成。
