# 增量备份节点安全删除与自动链重建

实现日期：2026-10-03。分支：`codex/safe-history-node-deletion`。

## 用户行为

历史页面默认选择“删除本地备份并隐藏记录（保留后续版本）”。选择操作后，先生成并验证替代链，再显示一次最终删除确认，列出重建版本数、新增归档大小、可回收大小和净释放大小。净释放为负数表示手动删除会增加占用。

“仅隐藏历史记录”不重写归档；“仅删除本地备份文件”保留历史条目。分析、重建、验证和等待确认时可以取消；进入提交边界后完成事务，再返回结果，不在元数据和本地登记之间中断。

删除依赖节点不会删除其他分支的保留版本。固定版本、当前工作区基准、活动安全快照及未完成合并会继续限制删除。加密归档必须提供有效凭据；缺失归档需要先下载或修复，不会隐式下载云端数据。

自动清理复用相同引擎，保持原来的保留数量和保护根规则；`KeepCount=0` 表示无限保留。自动清理不隐藏历史条目，只有按实际产物大小计算能够净释放空间时才提交。文件被占用导致回收延迟时，暂时保留旧字节，后续恢复重试，因此实际占用可能暂时高于完成回收后的占用。

## 存储算法与接口

`HistoryChainRewritePlanner.PlanAsync` 在历史变更门内冻结 Catalog、表示图、保留版本、重建步骤和状态指纹。`HistoryChainRewriteExecutor.PrepareAsync` 创建替代归档与最终回收集合；`CommitAsync` 复核状态后提交。

例如删除 B：

```text
原存储依赖：A_full → B_delta → C_delta → D_delta
增量合成后：A_full → C'_delta → D'_delta
全量替代后：         C'_full  → D'_delta
```

这些箭头表示归档依赖。C 和 D 的逻辑版本 ID、历史时间、备注、检查点和分支关系不变。D′可以复用 D 的归档字节，只新增依赖重定向后的不可变表示。旧表示事实不修改，旧云端副本不退休。

实现顺序：

1. 优先选择移除目标副本后仍可精确恢复的已有表示；需要重定向时，验证已有替代表示与原状态等价。
2. 从旧归档恢复保留基准和边界节点的完整历史状态，按文件路径、SHA-256、大小、修改时间及现有恢复契约中的属性计算差异；不读取当前工作目录作为历史状态。
3. 合成新增、修改及删除集合。纯删除或变化相互抵消的空增量使用合法标记归档，恢复时去除标记。
4. 对后代建立新表示；父状态不变时复用原归档字节。所有受影响分支与连续删除区间在同一规划中处理。
5. 新归档执行 7-Zip 校验，并实际恢复每条替代链，与原状态逐文件比较；仅执行 `7z t` 不构成等价证明。

默认变化量阈值为未压缩文件字节的 80%。没有基准、目标为空、超过 `MaxSmartBackupsPerFull`，或当前增量编码不适合路径结构变化时采用全量。链长限制为 0 表示无限制。

当前结构判断保守：目录集合变化及大小写路径转换会选择全量，包括新增空目录。输出格式统一为 7z，沿用配置的加密要求。自动清理若优先全量方案不省空间，会再尝试符合结构与深度约束的增量方案；两者都不省空间则保留旧链。

物理文件按规范化路径去重计算，不能因为移除旧表示登记而删除新表示仍复用的文件。只能直接回收受控绝对路径文件；存在无法解析的稳定根登记时保守延后回收。

## 提交、恢复与后续备份

- 准备期间持有必要的归档读取保护，生成产物位于仓库独立操作目录。所有逻辑对比通过后，才允许确认提交。
- 新表示、版本释放策略和隐藏标记进入同一历史 Pack；Catalog 切换复用已有 repository journal。仅变更 Catalog 的删除重复携带一个相同的不可变事实，作为持久提交标记，不新增共享对象类型。
- 设备日志位于 `local-state/chain-rewrites/`，记录关联 Pack、替换映射、已验证文件见证与待回收文件。工作目录位于 `transactions/rewrite-<id>/`，新归档位于 `payloads/rewrite-<id>/`。
- 提交前失败或取消会清理本次产物，保持旧归档及历史可见性。提交后中断则先重放 Catalog、修复缓存，再执行幂等回收。
- 回收前核验保留链文件的长度与存储 SHA-256；新归档丢失或被改坏时不回收旧字节。待删除文件自身也必须与记录的大小和哈希一致，且没有剩余登记或活动合并保护。
- 新旧登记共享文件时保留文件。无法删除的文件报告为待回收，不将已持久化的重建报告成未提交。
- 启动时自动恢复；已缓存的 Runtime 通过下一次配置级备份或还原恢复入口处理未完成重建。未完成元数据或缓存恢复时，普通历史变更会被阻止。
- 采集基线缓存只迁移表示、路径、类型和深度，保留原文件状态及边界。失效缓存从可精确恢复的历史版本重建，并验证完整本地依赖闭包，避免下一次 Smart 备份重新引用旧链。

这里的精确性沿用现有文件恢复契约，不引入 ACL、链接或文件系统镜像语义；链接及有歧义的路径不参与重建。

## 验证结果

宿主 Release 回归：**764 通过，0 失败，0 跳过**。其中 40 个测试结果属于 `HistoryChainRewrite*` 和 `HistoryRewriteTreeTests`。真实归档用例调用系统 7-Zip；空间成本测试另使用真实可恢复的非压缩 ZIP，强制触发成本回退或跳过，生产输出仍为 7z。

覆盖内容包括：

- 中间增量、首个全量、末端版本及连续节点删除；多分支保留；后代字节复用；已有独立表示及额外本地副本优先。
- 修改覆盖、修改后删除、新增后删除、删除后重建、纯删除、空增量、空目标、同大小不同内容、时间戳、文件目录转换、中文长路径与空目录。
- 加密与错误凭据、未知旧版边界、损坏依赖、后续部分范围增量、缓存迁移及从历史重建缓存。
- KeepCount=0、低于数量上限、多个保留边界、固定版本、实际空间成本回退、无收益跳过及重复清理。
- 在产物生成、验证、安装 Pack、切换 Catalog、修复缓存和回收中注入失败；文件占用、空间不足、计划过期、重启幂等性、缓存 Runtime 恢复及新归档外部损坏。
- 本地重建不修改旧表示依赖和云端副本的活动状态。


Windows x64 MSI 应用构建：**通过，0 警告、0 错误**。测试结果保存于忽略的 `artifacts/safe-history-deletion/safe-history-deletion.trx`。新增 14 个中英文本地化资源键已检查一致性。

## 提交与边界

按以下顺序进行本地提交，不推送、不发布：

1. `feat(history): 增加备份链安全重建规划与策略选择`
2. `feat(backup): 实现增量合成与全量替代归档生成`
3. `feat(history): 实现依赖重定向与可恢复的重建事务`
4. `fix(backup): 防止链重建后采集基线引用失效归档`
5. `feat(history): 接入安全删除预览与默认删除流程`
6. `feat(retention): 使用统一链重建执行自动保留清理`
7. `test(history): 覆盖中间节点删除与重建故障恢复`
8. `docs(history): 说明安全删除机制与验收结果`

首版不提供云端物理删除、旧版迁移链重建、插件专用表示重建或批量选择界面。重建需要临时磁盘空间，并可能对多个历史状态进行解压和校验；当前实现优先保证正确性，不宣称流式压缩包拼接的性能。
