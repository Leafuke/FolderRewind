## 本轮继续审查发现并修复的问题

| 风险 | 最终处理 |
|---|---|
| 升级 drain 可发生在一致性副本与转换能力获取之间 | 副本创建前固定同一插件会话，验证、materializer 和流释放沿用该会话 |
| 长隔离路径使 Windows 拒绝 Core 回退的工作目录 | Host 临时根采用稳定摘要的短路径，保留权限、归属与实际卷预算 |
| rclone 两次命令之间退出，正常快照被当成未知刷新证据 | 为新快照登记来源；仅回收已保存或可信修订链覆盖的字节，未知旧证据继续保留 |
| Cloud Job 状态轮询与原子替换争用，被固化为日志损坏 | 同一运行时日志读写串行化，并读取固定文件代际；双读取者/100 次更新回归 |
| 失败下载的保护根在其他副本恢复成功后残留 | 完整导入与本地登记成功后释放同一表示的停止下载；保留活动下载与其他表示 |
| Native 加密头选项泄漏到正式 Core 链重写 | 仅在 Native envelope 打包入口启用；同时验证 Core 既有密码行为和 Native 名称保护 |
| checkpoint 完成后的草稿页脚、取消导航后的选中态不一致 | 基线更新后通知草稿状态，按实际 Frame 内容恢复导航选中态；截图与重启验收 |
| 临时传输文件缺少统一归属与回收 | 使用 Host 私有、短路径、独占归属的暂存工作区；有界读回与实际卷预算沿用统一入口 |

目标分支的配置保存、操作门、Cloud Job、迁移与恢复事务保留；来源的语义 codec、分块 recipe、自包含 checkpoint 与稳定来源视图重新接入上述架构。P2 双表示生产路径、配对状态和 archive-first 转换已移除。CoreFull 回退保持独立；Native 退役采用逻辑授权与闭包 GC，Core 继续链重写。

## 性能观测与后置工作

正式 Core 对照使用目标基线的实际代码、同一 7za、同配置与三次重复。17 组恢复场景的归档列表/测试/解压次数及未压缩写入估计完全一致。完整还原 Clean 中位数为 1756 → 1812 ms，Overwrite 为 3848 → 4042 ms。冷缓存及后台负载未控制，耗时作为观测记录，不据此宣称严格时间等价。

另在 8,829,473 字节世界副本上比较集成 Core 与 Native；两者全部 18 个来源状态相同，共 36 次字节一致恢复。每种场景除基线/checkpoint 外，预热后测三次：

| 场景 | Core 捕获中位数 ms | Native 捕获中位数 ms | Core 恢复中位数 ms | Native 恢复中位数 ms |
|---|---:|---:|---:|---:|
| 不变 | 120 | 189 | 105 | 168 |
| 稀疏变化 | 267 | 853 | 357 | 226 |
| 密集变化 | 252 | 1484 | 649 | 230 |
| 删除 | 273 | 520 | 957 | 228 |
| 自包含 checkpoint | 335 | 3698 | 118 | 163 |

这份语料上 Native 捕获和上传成本较高；稀疏变化三次上传合计 Core 104,373 字节、Native 201,916 字节。Native 的增量恢复较快。最大值、子进程峰值、Host 峰值和实际暂存空间采样见机器可读记录；25 ms 采样是下界，不替代资源上限验证。4096 节点轻量闭包边界夹具与超限拒绝已验证，未提高生产配额。
