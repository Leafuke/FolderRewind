# KnotLink 可读虚拟备份名

本修复仅修改 Host。现有 MineBackup-Mod 继续使用 `LIST_BACKUPS` 和 `RESTORE;file=...`，无需升级模组。本文提供人工验收步骤，不包含自动化测试或验收脚本。

## 协议行为

`LIST_BACKUPS` 的 `data` 仍是百分号编码的分号列表。安全且唯一的普通归档名保持原样；语义备份、文件名缺失或不适合旧列表、同名多版本条目改为以下形式：

```text
frv_[2026-10-22_20-15-30]打龙前_[a1b2c3d4e5f6]
frv_[2026-10-22_20-18-05]_[b2c3d4e5f607]
```

- 时间来自逻辑版本的创建时间，转换为 Host 本地时间。
- 注释使用当前有效备注，清理分隔符、路径字符、控制字符和中括号，最多保留 64 个 Unicode 字符。
- ID 默认为 12 位；同一目录的版本存在前缀冲突时，列表改用完整 32 位 ID，检查范围包含被抑制版本。
- 日期和注释只供显示，实际选择依据 ID。修改备注后，旧名称仍可使用。
- 真实文件名与虚拟名、或者短 ID 产生不同版本候选时返回歧义错误，不猜测版本。
- 保护查询、标记请求使用 `file=` 时，回执及对应事件回显请求值；备份成功事件和完成回执使用同一套引用规则。

虚拟名不是实体归档，不会写入文件系统或替代内部载荷路径。`LIST_VERSIONS` 的 JSON 和 manifest 版本保持不变。旧模组不能从这种名称提取独立时间字段，因此其时间展示和排序限制仍存在。

## 人工验收

### 混合备份、补全与还原

1. 使用专门的临时世界，先创建一个普通归档备份，再启用语义备份。分别在世界中留下可辨认的状态 A、B，并为两次语义备份设置不同备注。
2. 执行 `/mb list backups current`，并在 `/mb restore ` 后按 Tab。普通归档保留原名，两个语义版本分别具有可读的 `frv_` 名称，不应合并为 `payload.7z`。
3. 分别使用列表生成的还原命令选择 A、B，确认还原到对应状态。使用模组生成的带引号命令处理含空格的名称。
4. 另行确认不带备份名的 `/mb restore` 仍沿用当前工作区分支顶端的既有选择规则。

### 备注与旧名称

1. 为备份设置中文、空备注，以及包含空格、分号、斜杠、中括号和表情的备注。列表项不能被拆分，名称不能包含路径分隔符，超长备注应截断且不产生残缺代理字符。
2. 复制一个虚拟名，在 Host 修改对应版本的备注，再用复制的旧名称还原；仍应定位到同一版本。

### 保护回执

使用现有联动入口或手动 KnotLink 客户端，对同一虚拟名依次发送 `GET_IMPORTANCE`、`MARK_IMPORTANT;important=true`、`GET_IMPORTANCE`、`MARK_IMPORTANT;important=false`。每次都提供调用方要求的 `from/request_id` 和目标选择参数；`file` 按协议做百分号编码。

确认回执的 `file` 与请求解码后的原值完全一致，`version_id` 为完整 ID，`important` 与操作结果一致。检查普通备份和受保护备份的成功事件、最终回执，不应将语义载荷的 `payload.7z` 作为可用备份名返回。
