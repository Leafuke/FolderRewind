# FolderRewind Plugin System v3

The current development contract is API 3.5 (`FolderRewind.Plugin.Abstractions` 3.5.0). Configuration-level restore coordination receives all affected folders, an operation ID, and an explicit Restore/Checkout/Merge kind. The Host closes the once-only continuation when the coordinator returns and drains an already-started mutation. Both `RecoveryRequired` and `CommittedRecoveryRequired` outcomes prohibit automatic rejoin. Merge preparation (unpacking, resolutions, compression, hash validation, and round-trip verification) completes outside coordination; coordination only engages Sources with actual filesystem mutations unless safety snapshots expand the scope, and zero-mutation merges bypass game exit coordination entirely. Ordinary Restore invokes the staging-preparation contract with locked read-only current/target views and bounded relative-file proposals; changed proposals are applied by the Host transaction and make the Workspace baseline Derived.

Plugin System v3 targets FolderRewind 1.9.0 and uses the independently versioned, BCL-only `FolderRewind.Plugin.Abstractions` 3.5 contract. The App, a plugin product, and the Plugin API have separate version lines. Plugins activate in-process, so Manifest service declarations both gate access to FolderRewind's formal Host API and disclose user impact; they are not a .NET or OS security sandbox.

The Host owns configuration, backup/restore orchestration, immutable Artifact identity and graph transactions, History, retention, Cloud ordering, integrity, progress and cancellation. Plugins may propose revision-bound Config changes, contribute policies/scopes/consistency/coordinators/commands, and—when statically declared—transform a committed core Artifact into an owned semantic Artifact plus provide its restore materializer. They do not mutate old archives from an after-backup hook or bypass Safe Restore.

Distribution uses root-manifest `.frplugin` ZIPs. Installation validates every canonical path and expanded-size bound before staging, rejects bundled Abstractions, validates Manifest/settings/PE metadata without loading assemblies or executing plugin code, stores versioned current/previous known-good payloads, and records a recovery journal. Official Catalog and Manual provenance remain distinct; newly installed plugins default to Disabled and first execute only after explicit Enable.

Outside safe mode, startup also updates an already installed official MineRewind to the newer fixed-hash bundled package **before loading any plugin assembly**, independently of completed or suppressed v2 migration state. This uses the installation transaction and validates persisted settings and reachable owned artifacts; settings, configuration identities, provenance and Enabled Intent are retained. Manual builds and newer versions are not replaced, and an uninstalled plugin is not reinstalled by this update path. An update failure is logged explicitly. Current-world commands await plugin initialization; an active old integration without the target resolver reports `knotlink.current_save_plugin_upgrade_required` with its ID/version instead of silently returning an unavailable selector. See [the upgrade incident analysis](knotlink-bundled-upgrade-2026-10-02.md).

Runtime routing and physical cleanup are separate guarantees. Disable, replacement, rollback, and discard remove capabilities and cancel the plugin lifetime before giving `DeactivateAsync` a bounded five-second grace period. A timeout cannot retain the transition gate: the Host continues with logical isolation, reports `RequiresRestart`, and keeps the affected load context until restart. Destructive uninstall likewise uses a journal plus same-volume code/data quarantine, commits configuration atomically, and either rolls back or finishes cleanup during startup recovery.

The Host repository validates the bundled MineRewind artifact as a fixed-hash black box. MineRewind restores, builds, tests, and packs in its own repository against the public `FolderRewind.Plugin.Abstractions 3.5.0` NuGet package; neither repository uses the other's application source as a build input.

The current bundled MineRewind 1.9.3 candidate has `.frplugin` SHA-256 `9cf45bc4be235ec2c95beb4b4dcbf7d14184d66b2cd6c8e6d55206ae5fc35de5`. It coordinates every affected Minecraft Source at configuration scope, while zero-mutation operations bypass game exit handshakes. Preserve-player-data is an ordinary-Restore-only staging proposal; Checkout and Merge never enable it and the plugin performs no live-path write after the Host continuation. MineRewind intentionally registers no Minecraft-specific Merge provider: `.mca`, NBT, stats and advancements remain conservative file conflicts in 1.9.0.

## KnotLink and all-player preservation (API 3.5)

Semantic target selectors use the optional `IKnotLinkTargetResolver` extension on the integration capability. They resolve a stable config/folder ID and execute the same Host command; they never create a second backup/restore parameter implementation. The shared `KnotLinkCoreCommands` catalog drives option validation and funcList generation. Six MineRewind selector variants have unique discovery names, retain their original wire cmd, and inherit core operation arguments. Plugin descriptors may declare argument and signal metadata.

`RestoreRequestOptions.PreservePlayerDataOverride` and the matching staging request property carry null/true/false without collapsing explicit false. Old constructors retain their behavior; old preparation capabilities default to `SupportsPlayerDataOverride=false`, and an unsupported explicit override fails closed. An optional `IRestoreSourceView` extends read-only metadata views with the locked, managed relative-path inventory. The Host validates the entire proposal batch (4,096 files / 64 MiB) before writing staging and blocks error diagnostics. Ordinary Restore preserves selected fields for all UUIDs; Checkout/Merge do not invoke player preservation. Host restore-whitelist staging retains missing current paths without overriding archive content.

Remote Restore now defaults to Clean, and both explicit-folder and current-world calls may omit the archive to use semantic Quick Restore. Partial captures always apply Overwrite, even if a representation has Exact fidelity. `manifestVersion=3.0.0` documents the changed remote default; specVersion and the v2 wire protocol remain unchanged. See [storage evidence and validation](minecraft-player-storage-26.1.md). Real-game loading acceptance is pending; automated NBT fixtures do not certify Minecraft loading.
