# 文件夹独立分支与开发版历史重建

项目统一管理备份规则及自动化，每个文件夹分别拥有分支。同一个项目中的两个存档都可以有 main；备份、检出及合并一个存档不要求另一个存档建立基线，也不会切换它的分支。

按来源查看时，历史节点代表单源检查点。普通还原改变文件和内容基线，活动分支保持不变；检出才切换活动分支。从历史检查点创建的分支不会自动激活。

按批次查看时，记录一次操作的参与文件夹及备份时分支。未选择的文件夹不会被算作失败。批次还原清单使用本次记录的版本，默认选中当前可还原项；所选文件夹一起还原，提交前失败整体回滚，各自活动分支保持不变。

## 捕获、失败尝试与旧历史迁移

捕获前检查工作区健康及请求来源的基线引用。引用的版本必须存在且属于同一来源；提交时再次校验。未请求来源的缺失基线或边界变化不阻断本次独立备份；未完成的工作区事务仍须先恢复。

首次备份失败仅产生 BackupRun 操作事实，允许初始化该来源的 Unknown 本机状态，不建立版本、检查点或活动分支。已有来源的本机状态保持不变。

旧正式历史迁移的事实身份及内容由输入确定，Pack 与 Transaction 身份保持随机。切换前取消可重新迁移；切换后绑定保存失败仅重试绑定，不覆盖已经建立的仓库。重复导入保持同一事实只有一个定义。这与下文未发布开发版元数据归档重建是不同路径。

## 旧开发版数据

历史仓库格式 2 与工作区格式 3 不读取旧开发版 1.9.x 元数据。关闭应用后在仓库根目录运行：

```powershell
./scripts/maintenance/Archive-DevelopmentHistory.ps1 -WhatIf
./scripts/maintenance/Archive-DevelopmentHistory.ps1
```

默认目标是本次提供的 Store 应用配置目录。可通过 `-ConfigDirectory` 明确指定另一份配置；脚本所有移动目标均限定在该目录内。存在未完成事务时，先用旧应用完成恢复，脚本会停止操作。

旧 history 与配置快照保存到 `development-history-archives/<时间戳>/`。新空仓库与格式绑定一起建立，避免重新发现旧开发版记录。配置身份、来源文件和实际备份归档保留；旧记录不会自动回到列表。脚本不会在应用启动时运行。

## 人工界面检查

分支合并使用独立工作页：在高级历史中选择来源分支，进入“合并分支”，先分析并处理冲突，再“生成并审阅结果”，最后更新当前文件夹与目标分支。来源分支不移动。离开页面保留任务；停止准备和放弃任务是不同操作。

文本比较为只读行级差异，采用一侧会选择整个文件；二进制及结构冲突保守处理。最终审阅分别列出分支变化与当前目录实际写入，当前工作需要保护时创建快照。完整交互说明、提交记录及待人工验收项见 [合并工作页重构记录](plans/Branch_Merge_Workspace_Refactor_2026-10-04.md)。
