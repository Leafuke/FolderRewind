# GitHub 一键正式发布

在 GitHub Actions 打开 **Release Setup**，选择源码分支并点击 **Run workflow**。无必填参数，无第二次人工放行；成功后自动生成对应版本的公开 Latest Release。版本、更新说明与代码变更需预先提交。该工作流文件必须存在于默认分支和选择的分支。

流程：预检查 → 核心测试、x64/ARM64 安装包并行 → 汇总冻结证据 → 上传草稿并核验 → 自动公开。两架构仅构建 Setup EXE，MSI 是内嵌载荷。最终公开四个附件：两个 EXE 和对应 SHA-256。

发布保留三个测试项目的完整用例、严格编译、PRI/资源校验、负向资源测试、MSI ICE、生产身份/无故障注入、原生注册表测试及迁移插件检查。版本 2 报告标记安装体验未执行；手动触发不伪造安装体验通过。

**Plugin v3 Hardening** 继续执行完整 CI、额外架构构建和 20 轮上传取消压力测试。**Installer Diagnostics** 手动执行两架构 MSIX 打包回归及 x64 隔离安装/回滚诊断。它们独立于正式发布，历史诊断失败仍保留。

更新说明读取顺序：`docs/release/FolderRewind-<三段版本>-notes.md`、`.github/release-notes/v<三段版本>.md`、GitHub 自动生成。安装包命名和现有未签名状态不变。

同一版本已公开时会核验标签指向、附件名单、GitHub digest 和下载的校验文件；一致则跳过构建。冲突时失败，不移动标签，不覆盖或删除已有附件。上传失败留下草稿，点击 **Re-run failed jobs** 继续本次运行的冻结文件。失败日志及验收报告在运行 artifacts 中。

此前完整 CI 基线为 944 秒，安装包构建约 520 秒（其中 MSIX 约 190 秒）。新版移除正式链路的 MSIX 和清理，测试与构建并行，目标约 8 分钟量级；GitHub 队列、网络和缓存会影响实际耗时。每次新发行摘要记录阶段耗时、发布时累计耗时、提交及文件哈希；首轮正式发布据此对比基线。
